# Reproducibility Package — AI-Driven Metadata Management for Modern Data Warehouse and Lakehouse Architectures

## Purpose
This package reproduces the controlled experiments reported in the validated manuscript. It deliberately separates three evidence classes: (1) externally verifiable public facts from NYC TLC and project documentation; (2) measurements generated by the included scripts; and (3) synthetic-scale catalog records used only to test retrieval scaling.

## Public evidence
NYC TLC publishes monthly trip-record data and data dictionaries. Its public trip-record page states that, for 2025 data onward, `cbd_congestion_fee` was added to Yellow, Green, and High Volume FHV datasets. The Yellow Taxi data dictionary defines the field as the per-trip charge for the MTA Congestion Relief Zone beginning Jan. 5, 2025. See `data/SOURCES.csv`.

The OpenMetadata cluster-sizing runbook is included only as external context for production-scale benchmarking; its numbers are not mixed with this package's local TF-IDF benchmark.

## Package layout
- `data/SOURCES.csv` — authoritative source links and roles.
- `data/semantic_corpus.csv` — generated after running the experiment script.
- `src/run_experiments.py` — corpus generation, leakage-safe semantic classification, and retrieval benchmark.
- `src/generate_charts.py` — regenerates publication charts from machine-readable outputs.
- `results/classification_metrics.json` — raw classification metrics and confusion matrix.
- `results/benchmark_summary.csv` — benchmark summary.
- `results/runtime_environment.json` — captured runtime versions.
- `figures/` — regenerated PNG charts.
- `environment.yml` and `requirements.txt` — reproducible software specification.
- `docs/DATA_CODE_AVAILABILITY.md` — manuscript-ready availability statement.

## Method 1: semantic classification
Twenty TLC-derived fields are mapped to five coarse semantic classes: financial, identifier, location, operational, and temporal. Twelve controlled textual variants are generated per field (240 rows total). Six complete field identities are held out: `fare_amount`, `tolls_amount`, `RatecodeID`, `PULocationID`, `trip_distance`, and `tpep_dropoff_datetime`. This prevents paraphrases of a held-out field from appearing in training. TF-IDF unigram/bigram features feed class-balanced logistic regression with random seed 42. Reported metrics are accuracy, macro-F1, per-class metrics, and the confusion matrix.

## Method 2: retrieval benchmark
The benchmark creates 10K, 50K, and 100K synthetic metadata entities seeded from the TLC-derived field vocabulary. Five queries are executed 20 times each after warm-up. It measures TF-IDF index build time and p50/p95/p99 sparse retrieval latency. It excludes network calls, authentication, graph traversal, distributed search, UI rendering, and concurrent production load. Therefore it is a component-level benchmark, not an Apache Atlas, DataHub, Amundsen, OpenMetadata, or commercial-catalog benchmark.

## Run
```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
python src/run_experiments.py
python src/generate_charts.py
```

## Expected manuscript classification result
The validated manuscript reports 72 held-out observations, accuracy approximately 0.667 and macro-F1 approximately 0.535. Location and temporal held-out examples are recovered strongly, while the baseline fails on unseen identifier and operational fields. This is intentionally retained as a negative/limiting result supporting the governance argument.

## Benchmark reproducibility
Exact wall-clock latency will vary by CPU, memory, virtualization, BLAS implementation, OS scheduling, and package versions. Do not require bit-for-bit timing equality. Validate the methodology, entity counts, query count, and broad scaling trend. For an archival replication, run at least three independent benchmark sessions and record hardware specifications.

## Research-integrity notes
- Do not describe the 10K–100K catalog as a real NYC TLC metadata catalog.
- Do not substitute OpenMetadata's published benchmark values for the local benchmark.
- Do not claim the classifier generalizes to arbitrary enterprise metadata.
- Keep the held-out field split unchanged when reproducing the manuscript numbers.
- Preserve raw outputs and the exact release used for publication.
